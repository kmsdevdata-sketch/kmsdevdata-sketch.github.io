이미지 빌드부터 ECS 서비스 갱신까지 자동화했습니다

애플리케이션은 ECS on EC2에서 실행하고, GitHub Actions가 이미지 빌드부터 서비스 갱신까지 수행합니다. 인증 정보와 실행 상태를 별도 운영 경계로 분리했습니다.

Runtime

Spring Boot 애플리케이션은 ECS on EC2에서 컨테이너로 실행합니다. RDS PostgreSQL은 영속 데이터를, ElastiCache Valkey는 캐시와 Redis Pub/Sub을 담당합니다.

Configuration & Secrets

설정과 Secret은 SSM Parameter Store에서 ECS Task Definition으로 주입합니다. 저장소와 배포 로그에서 인증 정보를 분리하고 환경별 설정은 Task Definition이 참조하도록 구성했습니다.

Health & Logs

Actuator Health Check로 ALB Target 상태와 배포 성공 여부를 확인하고, 애플리케이션 로그는 CloudWatch Logs로 전달해 배포 이후의 실행 상태를 확인했습니다.

확장을 고려한 이벤트 전달

WebSocket 연결은 각 ECS Task가 유지하지만 주문과 상담 이벤트는 Redis Pub/Sub으로 공유합니다. Task가 늘어나도 요청을 처리한 인스턴스와 사용자가 연결된 인스턴스 사이에서 같은 이벤트 흐름을 유지하도록 구성했습니다.
