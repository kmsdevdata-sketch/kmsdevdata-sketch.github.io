Technical Challenges

트랜잭션과 실시간 타임라인의 일관성

DB 저장 직후 WebSocket 이벤트를 먼저 발행하면 클라이언트의 REST 재조회가 커밋보다 먼저 실행될 수 있습니다. 타임라인 데이터는 트랜잭션 안에서 저장하고 실시간 발행은 AFTER_COMMIT 단계에서 수행했습니다. Redis Pub/Sub으로 여러 애플리케이션 인스턴스에 이벤트를 전달하고, 채팅방 Topic과 사용자별 문의 Topic의 책임을 분리했습니다.

주문 스냅샷과 현재 상담 상태 분리

문의방의 현재 참조 이미지를 과거 주문에서도 사용하면 이미지 변경 시 이전 기록까지 바뀝니다. OrderFormSubmission에 제출 당시 이미지를 저장하고 주문 CTA와 상세 조회가 해당 스냅샷을 사용하도록 변경했습니다. 주문서별 sellerViewedAt과 현재 submission 식별값을 분리해 과거 이벤트가 현재 상담을 오염시키지 않도록 했습니다.

결제 멱등성과 상태 추적

새로고침, 네트워크 재시도와 중복 클릭으로 같은 주문확인서에 결제 요청이 반복될 수 있습니다. 외부 결제 요청을 PaymentAttempt로 별도 관리하고 진행 중인 시도를 재사용했습니다. 완료 처리에서는 기존 주문과 결제 상태를 확인해 반복 요청에도 주문이 중복 생성되지 않도록 했습니다.

비동기 이미지 처리

원본 저장과 variant 생성을 분리하고 SQS를 버퍼로 사용해 API 응답이 이미지 처리 시간에 종속되지 않도록 했습니다. 클라이언트는 저장소 경로를 직접 조합하지 않고 백엔드가 제공하는 에셋 상태와 deliveryUrl을 사용합니다.
