05 · Backend Architecture

변경이 잦은 외부 연동을 Port 뒤로 분리했습니다

주문과 상담 규칙이 Redis, JPA, 결제 API 같은 기술 구현에 직접 묶이지 않도록 헥사고날 아키텍처의 의존 방향을 적용했습니다.

Inbound & Application

REST Controller, WebSocket/STOMP Endpoint와 Security가 요청을 받습니다. Provided Port는 실행 가능한 유스케이스를 정의하고, Application 계층은 트랜잭션과 도메인 호출 순서를 조율합니다.

Domain & Outbound

Domain은 주문, 상담, 결제와 환불 규칙을 보유합니다. Required Port가 영속성, 실시간 이벤트와 외부 API를 추상화하고 JPA, Redis, AWS, Cognito와 Point3 Adapter가 이를 구현합니다.

이 구조를 선택한 이유

주문과 상담 규칙을 Point3, Redis, S3 같은 외부 기술의 변경과 분리하고, 유스케이스 단위로 트랜잭션과 테스트 경계를 드러내기 위해 Port와 Adapter 구조를 적용했습니다.

프로젝트 규모에 맞춘 적용

3개월의 개발 기간과 팀 규모를 고려해 Domain Model과 JPA Entity를 별도로 이중화하지 않았습니다. 대신 상태 변경은 도메인 메서드로 제한하고, Application 계층은 구체적인 Infrastructure 구현체가 아닌 Port에 의존하도록 구성했습니다.
