Backend Architecture

비즈니스 도메인별 패키지 구조와 헥사고날 아키텍처의 의존 방향을 적용했습니다. Controller부터 Provided Port, Application, Domain, Required Port와 Outbound Adapter로 이어지는 구조입니다.

Inbound & Application

REST Controller, WebSocket/STOMP Endpoint와 Security가 Inbound Adapter 역할을 담당합니다. Provided Port는 실행 가능한 유스케이스 계약을 정의하고 Application은 실행 순서, 트랜잭션, 도메인 및 Port 호출을 조율합니다.

Domain & Outbound

Domain은 주문, 상담, 결제와 환불의 상태 및 규칙을 보유합니다. Required Port가 영속성, 실시간 이벤트, 객체 저장소, 메시지 큐와 외부 API를 추상화하고 JPA, Redis, AWS, Cognito, Point3 Adapter가 이를 구현합니다.

Decision

  • 비즈니스 규칙과 기술 구현의 변경 범위 분리
  • 유스케이스 단위 트랜잭션과 작업 경계 표현
  • 외부 기술을 Port 뒤로 격리
  • AI 작업을 유스케이스 또는 어댑터 단위로 제한

Trade-off

  • Domain Model과 JPA Entity를 통합해 매핑 제약이 일부 남음
  • 단순 기능에도 Port와 Adapter 구조 비용이 발생
  • 일부 초기 기능은 Application Service의 책임이 큼
