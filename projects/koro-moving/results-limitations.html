10 · 결과와 다음 단계

동일한 결과물을 두 환경에 배포하고 검증된 환경으로 전환했습니다

구현 결과

  • 한 번 빌드한 이미지를 AWS와 온프레미스에 배포하고 전환
  • 실제 서비스 URL이 정상인 경우에만 배포 완료
  • 같은 요청이 반복되거나 동시에 들어와도 한 번만 실행
  • Agent 재시작 후 기존 컨테이너와 Tunnel 자동 복구
  • 온프레미스 장애 시 검증된 AWS 환경으로 자동 전환
  • 13개 시나리오와 61회 실제 배포로 주요 흐름 확인

다음 검증 단계

  • 상태가 있는 서비스까지 전환하려면 DB와 파일 동기화 방식이 필요
  • 장시간 운영에서 Agent heartbeat와 Tunnel 재연결 안정성 측정
  • 여러 컨테이너로 구성된 애플리케이션의 배포 단위 확장
  • DNS와 외부 서비스 지연을 포함한 전환 시간 분포 관찰
  • 다수 프로젝트가 동시에 배포될 때 Queue와 Agent 처리량 검증

프로젝트에서 얻은 기준

배포 명령의 성공만으로 운영 환경을 바꾸지 않고, 후보 환경과 공개 URL을 차례로 검증해야 했습니다. 이 기준을 작업 상태, Agent 복구와 Failover에 함께 적용하면서 배포 기능의 완료 범위를 실행 명령이 아니라 사용자가 접속할 수 있는 상태까지 넓혔습니다.
