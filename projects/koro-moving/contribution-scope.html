03

Contribution & Scope

배포 이후 사용자가 실제 서비스에 접속할 수 있는 상태까지 책임지는 영역을 담당했습니다. 아래는 직접 설계·구현한 기능과 그 구현 방식입니다.

배포 완료 판단

  • 기능 실제 서비스가 안정적으로 응답한 경우에만 배포 완료
  • 구현 최대 8회 확인하고 3회 연속 성공을 요구
  • 기능 중복 요청으로 같은 배포가 두 번 실행되는 상황 차단
  • 구현 요청 내용의 SHA-256 fingerprint와 Job ID 비교

온프레미스 배포

  • 기능 사용자 장비에서 동일한 컨테이너 이미지 실행
  • 구현 Agent가 ECR 이미지를 digest 기준으로 내려받아 Docker Compose 실행
  • 기능 로컬 서비스를 외부에서 접근 가능한 URL로 제공
  • 구현 로컬 확인 후 Cloudflare Named Tunnel 연결

복구와 환경 전환

  • 기능 Agent 재시작 후 기존 컨테이너와 Tunnel 복구
  • 구현 실행 상태를 저장하고 서버의 목표 상태와 다시 비교
  • 기능 온프레미스 장애 시 검증된 AWS 환경으로 전환
  • 구현 Agent 연결과 공개 URL 장애를 함께 확인한 뒤 origin 변경

검증

  • 실제 PostgreSQL로 중복·동시 요청 제어 확인
  • AWS와 온프레미스 왕복 전환 자동 테스트
  • 공개 URL 응답 시간과 동시 배포 시나리오 측정
  • 실패 후 잠금과 실행 환경이 남지 않는지 확인

Analyzer/IR, 초기 이미지 빌드·ECR 파이프라인, 전체 Terraform 구성과 프론트엔드는 다른 팀원의 구현입니다. 이 페이지는 코드와 PR 이력으로 확인되는 범위만 정리했습니다.
