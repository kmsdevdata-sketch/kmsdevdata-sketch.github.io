03 · 기여 범위

온프레미스 실행과 실패 복구 흐름을 맡았습니다

배포 이후 사용자가 실제 서비스에 접속할 수 있는 상태까지 책임지는 영역을 맡았습니다. 같은 결과물을 AWS와 온프레미스에서 실행하고, 실패 시 기존 서비스를 보호하는 흐름에 집중했습니다.

사용자 관점의 완료 기준

내부 배포 명령이 끝났다는 상태만으로는 성공을 판단하기 어려웠습니다. 실제 서비스 URL의 연속 응답을 확인한 뒤 완료 처리하고, 재시도로 같은 작업이 중복 실행되지 않도록 요청 식별 기준을 함께 설계했습니다.

동일한 결과물의 온프레미스 실행

클라우드와 사용자 장비의 빌드 결과가 달라지지 않도록 ECR의 동일 image digest를 Agent가 내려받아 Docker Compose로 실행했습니다. 로컬 검증을 통과한 서비스만 Cloudflare Tunnel에 연결했습니다.

재시작과 장애를 고려한 복구

Agent의 실행 상태를 남기고 서버가 기대하는 상태와 다시 비교해, 재시작 이후에도 컨테이너와 Tunnel을 복구했습니다. 온프레미스 연결과 공개 URL 장애가 함께 확인될 때만 검증된 AWS 환경으로 전환했습니다.

검증 범위

  • 실제 PostgreSQL 환경에서 중복·동시 요청 제어 확인
  • AWS와 온프레미스 왕복 전환 자동 테스트
  • 공개 URL 응답 시간과 동시 배포 시나리오 측정
  • 실패 이후 잠금과 실행 환경 정리 여부 확인

매일 Slack으로 설계와 진행 상황을 공유하고, 의견이 다를 때는 근거와 실험 결과를 바탕으로 방향을 정했습니다. 대회 현장에서는 Progate 관계자와 두 차례 인터뷰하고, 배포 대상의 메타데이터와 온프레미스 실행 방식에 대한 기술 피드백을 반영해 설계를 보완했습니다.
