Recovery, Cleanup & Failover

Failover Timeline

실패해도 다시 이어지는 정리 작업

현재 운영 환경과 복구용 환경만 남기되, 정리 작업 자체도 PostgreSQL에 기록했습니다. 서버 재시작이나 일시적인 실패가 발생해도 남은 작업을 다시 이어갈 수 있습니다.

전환 가능한 환경만 Standby로 유지

단순히 실행 중인 환경이 아니라 현재 운영 이미지와 같은 digest로 배포되고 검증까지 통과한 환경만 standby로 인정했습니다. 전환 가능성이 확인되지 않은 환경은 복구 후보에서 제외했습니다.

두 신호로 장애 오판 줄이기

순간적인 네트워크 지연만으로 환경이 바뀌지 않도록 Agent 연결 단절과 공개 URL 3회 연속 실패가 함께 발생한 경우에만 장애로 판단했습니다.

새로 만들지 않고 검증된 AWS로 전환

장애 시점에 인프라를 새로 만드는 대신 동일 이미지로 미리 검증한 AWS 환경으로 Cloudflare origin을 변경했습니다. 전환 후 공개 URL을 다시 확인해 사용자의 고정 주소를 유지했습니다.

온프레미스 연결과 실제 서비스 응답이 모두 실패한 경우에만, 사전에 검증된 동일 이미지의 AWS 환경으로 전환합니다.
