10 · 운영 개선 계획

반복 가능한 배포와 장애 대응을 다음 운영 기준으로 잡았습니다

보안 경계 정리

  • ECS Task 전용 Security Group을 분리하고 RDS 인바운드를 해당 Task로 제한
  • 데이터베이스 비밀번호와 callback token을 Secrets Manager 또는 Parameter Store로 이전
  • API Key 사용량과 요청 제한을 프로젝트 단위로 기록

장애 대응 자동화

  • SQS 적체와 DLQ 유입을 CloudWatch Alarm으로 연결
  • 실패 메시지를 원인별로 확인하고 다시 처리하는 redrive 절차 구성
  • Asset 화면에서 원본과 variant 처리 상태를 함께 표시

재현 가능한 인프라

콘솔에서 만든 VPC, ECS, RDS, SQS와 Lambda 구성을 Terraform 또는 AWS CDK로 옮길 계획입니다. 새 환경을 같은 설정으로 다시 만들 수 있어야 네트워크와 권한 변경도 코드 리뷰와 이력 관리의 대상으로 다룰 수 있습니다.
