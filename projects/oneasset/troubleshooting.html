09 · Troubleshooting

증상이 나타난 구간을 요청 경로와 실행 경로로 나눠 추적했습니다

배포 실패처럼 보이는 증상도 실제 원인은 서로 달랐습니다. 외부 요청이 애플리케이션에 도달하는 경로, ECS Task가 외부 서비스로 나가는 경로, Lambda가 결과를 돌려주는 경로를 분리해 확인했습니다.

Cloudflare 경유 요청이 약 20초 동안 지연됨

재현과 추적

애플리케이션 로그가 남기 전에 응답이 지연되어 Spring Boot 처리 시간이 원인이 아님을 확인했습니다. Cloudflare, ALB, Target Group 순서로 요청 도달 여부와 subnet 구성을 비교했습니다.

원인

외부 요청을 받는 ALB와 애플리케이션을 실행하는 ECS Task의 네트워크 역할이 섞여 있었습니다. Target이 배치된 AZ도 ALB enabled AZ와 일치하지 않아 503이 함께 발생했습니다.

수정과 확인

ALB는 public subnet, ECS Task는 private subnet에 배치하고 양쪽 AZ를 맞췄습니다. 이후 Target Health가 정상으로 전환되고 Cloudflare 도메인 요청이 Task까지 바로 전달되는지 확인했습니다.

Private subnet의 Task에서 Cognito metadata를 읽지 못함

재현과 추적

ALB Health Check는 통과했지만 인증 요청에서만 timeout이 발생했습니다. Task 내부에서 Cognito metadata와 AWS public endpoint로 나가는 연결을 각각 확인했습니다.

원인

Private subnet의 route table에 외부로 나가는 경로가 없어 JWT 검증에 필요한 Cognito metadata를 가져올 수 없었습니다.

수정과 확인

NAT Gateway와 private route table을 연결한 뒤 Task에서 metadata endpoint 접근과 인증 API를 다시 확인했습니다. 인바운드는 ALB로 제한하면서 필요한 아웃바운드 통신을 분리했습니다.

이미지는 변환됐지만 Asset이 READY로 바뀌지 않음

재현과 추적

S3에는 WebP variant가 생성됐지만 DB 상태는 PROCESSING에 머물렀습니다. Lambda 로그에서 변환 완료 뒤 internal callback이 401 또는 timeout으로 끝나는 구간을 찾았습니다.

원인

Lambda와 ECS에 주입된 callback token이 달랐고, 기본 3초 timeout으로는 이미지 변환과 callback까지 마치기 어려웠습니다.

수정과 확인

두 런타임의 token을 같은 설정값으로 맞추고 Lambda timeout을 30초로 조정했습니다. 이후 variant 저장, callback, READY 전이가 한 흐름으로 완료되는지 업로드 시나리오로 확인했습니다.
